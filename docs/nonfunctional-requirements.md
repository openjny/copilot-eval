# 共通の非機能要件

草案。機能をまたいで守る条件を置く。以下は要求であって、検証済みの保証ではない。ID は既存 spec からの参照を維持するために残す。

## 実際のプロジェクトで動かせる

**NFR-001 / 対応環境:** 第一段階は Linux と Windows のコード・コマンドを使うプロジェクトを対象とする。Windows 上で実行・検証できることを確認し、クライアントが起動するだけで対応済みとはしない。GUI 環境の自動構築は含めない。対応版は使用するツールチェーンを選んでから、動作確認した組み合わせを記録する。

**NFR-002 / 導入負担:** ローカル比較のために、未使用のクラウド・学習・ダッシュボードの依存まで導入させない。依存を選ぶときは導入量・時間、起動・更新の手間を確認する。現段階で根拠のない容量・メモリの上限値は設けない。

**NFR-003 / 想定規模:** 普段はタスク・条件ごとの反復を合わせて数十〜数百回の実行予定を扱う。この規模での使いやすさを優先するが、数百回を製品の上限にはしない。指定した並列上限の下で資源消費・待機時間を計測し、再試行で増える Task Run も含めて、モデルの応答待ちと本体の負荷を区別する。性能目標は代表的な実験で測定してから決める。

## 失敗しても調査・回復できる

**NFR-004 / 回復:** 障害や停止で取得済み記録を失わず、残った管理資源を確認できるようにする。継続・停止・再試行・再開の動作は [実行管理 spec](../specs/002-execution-management/spec.md) に従う。実行マシンの電源断後の自動継続は保証しない。保存方式の選択時に、どの障害まで回復できるかを確認する。

**NFR-007 / 結果の解釈:** [共通モデルの記録・評価・比較](domain-model.md#記録評価比較)のルールに従い、比較結果から証拠へたどれるようにする。保持期間、出力の打ち切り、エクスポート方式を決める際も、何を取得・省略したかが分かることを保つ。

## 秘密情報と利用者の環境を守る

**NFR-005 / 信頼境界:** 信頼済みの実験を記述したファイル・コードと、実行中に生成されるコマンドを同一視しない。必要な認証だけを実行先へ渡し、設定保存・ログ・結果表示に秘密値を残さない。後片付けで既存プロジェクトや共有サービスを削除しない。認証の取得・破棄と記録の秘匿方法は、実行・保存の設計と合わせて確認する。

**NFR-006 / 制限の保証:** ファイル、プロセス・サービス、通信先、取得内容の制御は [共通モデル](domain-model.md#環境と実行先)で区別する。それぞれが各 OS・実行先でどこまで強制できるかを示し、未確認の同等性を保証しない。強制できない環境の実行可否は技術検証後に判断する。

**NFR-008 / 利用条件:** 利用者は OS・ツール・モデル・資料の利用権限を用意する。製品は送信先と課金条件を確認でき、機密情報を含まない診断情報を提供する。依存の採用・配布時にライセンスと利用規約を確認する。

機能ごとの受入れシナリオは [spec](../specs/README.md) に置く。本書の条件を実測した際は、その証拠へのリンクを追加する。
