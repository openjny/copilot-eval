# Copilot Eval Constitution

状態: 承認済み。2026-09-12 に開発者が原則5項目と例外手続きを承認した。

## Core Principles

### I. 比較の意味を保つ

実装上の都合で比較の意味を変えない。条件・反復・再試行・評価の解釈は [共通ドメインモデル](../../docs/domain-model.md) に従い、モデルや基盤の暗黙動作を製品の観測結果として扱わない。

### II. 判断できる証拠を残す

品質・使用量の主張は対象条件と証拠へ追跡できなければならない。情報の確度と欠測は共通モデルの規則に従う。文書の生成、チェックリストの完了、実装、動作検証を混同しない。

### III. 共通の約束を局所変更しない

feature の要求・設計・実装は、共通モデルと全体設計への影響を確認する。語の意味や共有契約を変更する場合は正本を更新し、関係する feature と整合させる。重複記述で別の正本を作らない。

### IV. 実際の利用環境で成立させる

[共通非機能要件](../../docs/nonfunctional-requirements.md) の対応環境・信頼境界・導入負担を方式選定から確認する。ある実行先での成功を別の OS・実行先の保証に拡張しない。

### V. 要求に必要な複雑さだけを持つ

独自実装や汎用化そのものを目的にしない。依存や抽象化の追加は、既存機能の再利用と比較して必要性を説明する。実験の操作方法ではなく、[製品方針](../../docs/product-vision.md) の利用者価値を判断基準にする。

## Governance

Spec Kit の要求・計画レビューで原則への適合を確認する。矛盾を原則の黙った弱体化で解消せず、要求・設計の修正または明示的な原則改訂として扱う。例外は理由・範囲・影響・確認方法を示し、承認されるまで採用しない。

改訂は開発フローの影響確認と判断記録に従う。承認済み版の原則を互換性なく変更する場合は MAJOR、原則の追加・拡張は MINOR、意味を変えない修正は PATCH とする。
