## User Scenarios & Testing

### UC-011: ダッシュボードで操作・調査する

- アクター: 利用者。提供段階: 後続。
- 目的: 複数実験を見渡し、結果比較と原因調査から次の実行へ進む。
- 前提／入力: 定義済み条件と、実行済みまたは実行中の比較。
- 操作と応答: 実験一覧・条件・状況を確認し、開始・停止・再開を行う。条件比較から個別記録へ進み、戻ったときも選択条件を維持する。
- 例外: 空の結果、実行中、失敗、欠測を区別し、配色だけで状態を伝えない。閲覧によって実行・評価を開始しない。
- 完了条件: 条件の違いと品質・費用を確認し、指示・ツール応答・成果物へたどれる。

### UC-012: PR のカスタマイズ変更を評価する

- アクター: 利用者。提供段階: 後続候補。
- 目的: 指定した primitives の変更を継続的に評価する。
- 前提／入力: PR の変更対象パスと実験の対応。
- 操作と応答: CI から指定実験を実行し、条件・評価・使用量・失敗・詳細記録への参照を PR へ掲載する。
- 例外: 低評価だけで CI を失敗させない。起動失敗や設定不備は別に通知する。信頼されていない PR のコードや hooks に秘密情報を渡す運用を標準にしない。
- 完了条件: PR から変更に対応する評価結果と実行失敗を区別して確認できる。

## Requirements

基礎となる結果と操作は [ローカル比較](../001-local-comparison/spec.md)、[実行管理](../002-execution-management/spec.md)を参照し、本書で再定義しない。CLI を置き換えるものではない。

画面編集、認証・公開、複数利用者の範囲は TBD。PR への改善提案は将来検討し、自動修正・改善案の自動採用は含めない。変更前後の自動比較は別の後続候補。

可視化の候補に、精度と使用量・費用の関係を示すパレート図を含む。表示形式の採用は TBD。複数利用者の権限・秘密情報・結果閲覧の分離は将来のサービス向けで、第一段階に利用者管理サービスを要求しない。

## Success Criteria

- 画面の一覧→条件比較→個別試行→一覧で、関連記録と選択条件を追えること。
- 低評価と基盤障害の確認例で、PR掲載内容と CI の扱いが区別されること。
- 無権限・空データ・途中状態・秘密情報の扱いを確認すること。

確認手順・環境・水準・担当・期限は TBD。旧 REQ-031・032 は本文未定義のため [移行索引](../README.md)で TBD として管理する。
